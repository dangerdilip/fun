SECTION 2 — index.html STRUCTURE
════════════════════════════════════════════════════════════════════════════════

The index.html is the single entry point. Everything runs through it.
It contains all screen layers stacked on top of each other.
Only the active screen is visible at any time (others display:none).

LAYER STACK (bottom to top, all position:fixed, full screen):
    Layer 0 — Three.js Canvas         (the 3D game world)
    Layer 1 — Background Video        (for menu/splash screens only)
    Layer 2 — Screen UI Panels        (menus, character select, etc.)
    Layer 3 — In-Game HUD             (health bars, mana, timer, round)
    Layer 4 — Cinematic Overlay       (dims UI during specials)
    Layer 5 — Screen Transition       (fade in/out between screens)

HTML SCREEN IDs (each is a div, shown/hidden by UIManager.js):
    #screen-splash          ← Splash / boot screen
    #screen-main-menu       ← Main menu
    #screen-lobby           ← Multiplayer lobby
    #screen-char-select     ← Character selection
    #screen-arena-select    ← Arena selection
    #screen-loading         ← Loading screen
    #screen-hud             ← In-game HUD (overlays canvas)
    #screen-post-match      ← Winner, rematch options
    #screen-pause           ← Pause overlay
    #screen-settings        ← Settings overlay

IMPORTANT: The Three.js canvas (#game-canvas) is always rendering in the
background. Screens are HTML/CSS layers on top. When in-game, all screens
except #screen-hud are hidden. The HUD is always transparent background.

EXTERNAL LIBRARIES LOADED VIA CDN IN index.html:
    Three.js        : https://cdn.jsdelivr.net/npm/three@latest/build/three.min.js
    GLTFLoader      : https://cdn.jsdelivr.net/npm/three@latest/examples/js/loaders/GLTFLoader.js
    AnimationMixer  : Included in Three.js core
    Rapier.js       : https://cdn.jsdelivr.net/npm/@dimforge/rapier3d-compat/rapier.min.js
    Google Fonts    : https://fonts.googleapis.com/css2?family=Bebas+Neue&family=Rajdhani&family=Cinzel+Decorative
    Partykit        : https://cdn.jsdelivr.net/npm/partysocket/dist/partysocket.min.js

SECTION 3 — BACKGROUND VIDEO SYSTEM
════════════════════════════════════════════════════════════════════════════════

The background video is used on: Splash Screen, Main Menu, Character Select,
Arena Select. It is NOT visible during gameplay (canvas takes over).

────────────────────────────────────────────────────────────────────────────────
3.1 HOW THE VIDEO IS APPLIED (HTML/CSS Method)
────────────────────────────────────────────────────────────────────────────────

HTML ELEMENT:
    <video id="bg-video" autoplay muted loop playsinline>
        <source src="video/splash_bg.mp4" type="video/mp4">
    </video>

CSS STYLING:
    #bg-video {
        position: fixed;
        top: 0;
        left: 0;
        width: 100vw;
        height: 100vh;
        object-fit: cover;       ← Fills screen without stretching
        z-index: 0;              ← Behind all UI layers
        opacity: 0.6;            ← Dimmed so UI text is readable on top
        filter: brightness(0.5) saturate(1.2);  ← Dark and rich
    }

OVERLAY ON TOP OF VIDEO:
    A semi-transparent dark gradient div sits between video and UI:
    background: linear-gradient(
        to bottom,
        rgba(0,0,0,0.4) 0%,
        rgba(0,0,0,0.7) 100%
    );
    This ensures menu text is always readable regardless of video content.

────────────────────────────────────────────────────────────────────────────────
3.2 VIDEO SWITCHING BETWEEN SCREENS
────────────────────────────────────────────────────────────────────────────────

UIManager.js controls when video is visible:

    showVideo()   → sets #bg-video display:block, fades in over 0.5s
    hideVideo()   → fades out over 0.3s, then display:none

VIDEO IS SHOWN ON   : splash, main-menu, char-select, arena-select, lobby
VIDEO IS HIDDEN ON  : loading, in-game, post-match

When transitioning from menu to game:
    1. Fade to black (screen-transition layer opacity 0 → 1, 0.5s)
    2. Hide video (display:none)
    3. Show Three.js canvas fully
    4. Begin loading arena
    5. Fade from black when arena is ready

────────────────────────────────────────────────────────────────────────────────
3.3 VIDEO FORMAT REQUIREMENTS
────────────────────────────────────────────────────────────────────────────────

FORMAT          : MP4 (H.264 codec) — widest browser support
RESOLUTION      : 1920x1080 recommended (scales down automatically)
DURATION        : 10-30 seconds, seamless loop point
FILE SIZE       : Keep under 15MB for fast load. Use HandBrake (free) to
                  compress: https://handbrake.fr
CONTENT         : Slow cinematic arena footage, particle effects, atmospheric.
                  Can be a looping render from Blender or captured in-game later.
FALLBACK        : If video fails to load, CSS background-color: #0a0a0f
                  (very dark blue-black) is used instead.

────────────────────────────────────────────────────────────────────────────────
3.4 ALTERNATIVE — THREE.JS CANVAS AS BACKGROUND (Advanced)
────────────────────────────────────────────────────────────────────────────────

Instead of a video file, a simple Three.js scene can serve as the
animated background for menus — a slow rotating arena view with particles.
This removes the need for any video file.

IMPLEMENTATION:
    — Load arena GLB at low quality
    — Camera slowly orbits around centre
    — Particle system adds floating dust/embers
    — Menu HTML overlays on top of canvas
    — Switching to gameplay just changes camera mode and loads characters

This is the recommended approach if your video file is too large or
if you want a smaller overall project size.

SECTION 4 — GAME STATE MACHINE (GameState.js)
════════════════════════════════════════════════════════════════════════════════

The GameState is the central brain of the game. Every system checks it
before doing anything. Only one state is active at any time.

────────────────────────────────────────────────────────────────────────────────
4.1 ALL GAME STATES
────────────────────────────────────────────────────────────────────────────────

    STATE_SPLASH            → Showing splash screen, waiting for input
    STATE_MAIN_MENU         → Main menu displayed
    STATE_LOBBY             → Multiplayer lobby, waiting for connection
    STATE_CHAR_SELECT       → Players choosing characters
    STATE_ARENA_SELECT      → Players choosing arena
    STATE_LOADING           → Assets loading for match
    STATE_ROUND_INTRO       → "ROUND 1" text animating in, 2 second delay
    STATE_FIGHTING          → Active combat, all systems running
    STATE_ROUND_END         → KO or timeout, winner flash, 2 second hold
    STATE_MATCH_END         → Match winner decided, victory pose
    STATE_PAUSE             → Game paused (ESC key)
    STATE_POST_MATCH        → Rematch / menu options
    STATE_SETTINGS          → Settings overlay open

────────────────────────────────────────────────────────────────────────────────
4.2 STATE DATA STRUCTURE
────────────────────────────────────────────────────────────────────────────────

GameState stores:
    currentState        : string (one of above)
    previousState       : string (for returning from pause/settings)
    matchData : {
        player1 : {
            characterId     : "harshita" | "harshita_s" | "debojeet" | "ryomen_raj"
            roundsWon       : 0
        }
        player2 : {
            characterId     : string
            roundsWon       : 0
            isAI            : true | false
            aiDifficulty    : "easy" | "medium" | "hard"
        }
        selectedArena   : "temple" | "district"
        currentRound    : 1 | 2 | 3
        maxRounds       : 3
    }
    isMultiplayer       : true | false
    isHost              : true | false (multiplayer only)

────────────────────────────────────────────────────────────────────────────────
4.3 STATE TRANSITIONS
────────────────────────────────────────────────────────────────────────────────

    SPLASH          → (any key)         → MAIN_MENU
    MAIN_MENU       → (single player)   → CHAR_SELECT
    MAIN_MENU       → (multiplayer)     → LOBBY
    LOBBY           → (both ready)      → CHAR_SELECT
    CHAR_SELECT     → (both confirmed)  → ARENA_SELECT
    ARENA_SELECT    → (confirmed)       → LOADING
    LOADING         → (assets ready)    → ROUND_INTRO
    ROUND_INTRO     → (2s delay)        → FIGHTING
    FIGHTING        → (KO or timeout)   → ROUND_END
    ROUND_END       → (match not over)  → ROUND_INTRO (next round)
    ROUND_END       → (match over)      → MATCH_END
    MATCH_END       → (2s delay)        → POST_MATCH
    POST_MATCH      → (rematch)         → LOADING (same characters/arena)
    POST_MATCH      → (menu)            → MAIN_MENU
    FIGHTING        → (ESC)             → PAUSE
    PAUSE           → (resume)          → FIGHTING
    any             → (settings)        → SETTINGS
    SETTINGS        → (back)            → previousState

────────────────────────────────────────────────────────────────────────────────
5.2 CHARACTER INSTANCE STATE (CharacterController.js runtime)
────────────────────────────────────────────────────────────────────────────────

Each CharacterController instance tracks:

    // Identity
    data                    : HarshitaData (the static data object above)
    playerIndex             : 1 | 2

    // Position & Physics
    position                : THREE.Vector3
    velocity                : THREE.Vector3
    facingDirection         : 1 | -1  (1=right, -1=left, auto-updated)
    isGrounded              : bool
    isOnWall                : bool

    // Movement State
    isWalking               : bool
    isDashing               : bool
    dashTimer               : float (counts down, 0 = dash over)
    isCrouching             : bool
    isJumping               : bool
    jumpCount               : 0 | 1 | 2 (double jump tracking)

    // Combat State
    currentAction           : "idle"|"walk"|"attack"|"hit"|"block"|"knockdown"
    isAttacking             : bool
    attackPhase             : "startup"|"active"|"recovery"|null
    attackFrameTimer        : int (counts down frames)
    isBlocking              : bool
    isInvulnerable          : bool (during certain animations)
    canAct                  : bool (false during startup/recovery)
    isKnockedDown           : bool
    getUpTimer              : float

    // Resources
    currentHP               : float (0.0 to 100.0)
    currentMana             : float (0.0 to 100.0)
    guardMeter              : float (0.0 to 100.0, starts full)
    hasUsedRageArt          : bool (reset each round)

    // Animation
    mixer                   : THREE.AnimationMixer
    currentAnimation        : string
    animations              : { name: THREE.AnimationAction } map

    // Three.js
    model                   : THREE.Group (loaded GLB)
    hitboxMesh              : THREE.Mesh (invisible, for debug)

────────────────────────────────────────────────────────────────────────────────
5.3 CHARACTER FACING DIRECTION (Auto-Update)
────────────────────────────────────────────────────────────────────────────────

Characters always face each other. This is calculated every frame:

    function updateFacingDirection(player1, player2) {
        if (player1.position.x < player2.position.x) {
            player1.facingDirection = 1;   // faces right
            player2.facingDirection = -1;  // faces left
        } else {
            player1.facingDirection = -1;
            player2.facingDirection = 1;
        }
        // Apply to Three.js model rotation
        player1.model.rotation.y = player1.facingDirection === 1 ? 0 : Math.PI;
        player2.model.rotation.y = player2.facingDirection === 1 ? 0 : Math.PI;
    }

"Block" input is ALWAYS "hold away from opponent" regardless of which
side the character is on. InputManager handles this translation.

────────────────────────────────────────────────────────────────────────────────
5.4 CHARACTER LOADING PROCESS
────────────────────────────────────────────────────────────────────────────────

Loading order during LOADING state:

    STEP 1 : Load arena GLB → add to Three.js scene
    STEP 2 : Load character 1 GLB → position at x = -3, y = 0, z = 0
    STEP 3 : Load character 2 GLB → position at x = +3, y = 0, z = 0
    STEP 4 : Load all animation GLBs → attach to character mixers
    STEP 5 : Load all sounds for both characters into SoundSystem
    STEP 6 : Load arena music
    STEP 7 : Load UI assets (health bar textures, fonts)
    STEP 8 : Initialise physics world, create character capsules
    STEP 9 : Set currentAnimation to "idle" for both
    STEP 10: Transition to ROUND_INTRO state

Loading progress is tracked and shown on loading screen as percentage.

    totalAssets = (arenas + models + animations + sounds)
    loadedAssets = 0
    progress = loadedAssets / totalAssets * 100
    → Updates loading bar in HTML

SECTION 6 — INPUT SYSTEM (InputManager.js)
════════════════════════════════════════════════════════════════════════════════

InputManager listens to keyboard events and translates them into
game actions. It handles double-tap detection for dashes.

────────────────────────────────────────────────────────────────────────────────
6.1 KEY BINDINGS (Default)
────────────────────────────────────────────────────────────────────────────────

    PLAYER 1 (Keyboard — left side):
        W           → Move Forward
        S           → Move Backward / Block (when facing opponent)
        A           → Strafe Left
        D           → Strafe Right
        Space       → Jump / Double Jump
        Ctrl        → Crouch (hold)
        U           → Light Attack
        I           → Medium Attack
        O           → Heavy Attack
        J           → Combo String
        K           → Special Move (tap = full mana, hold 0.5s = half mana)
        ESC         → Pause

    PLAYER 2 (Keyboard — right side, for local testing):
        Arrow Keys  → Movement
        Numpad 1    → Light Attack
        Numpad 2    → Medium Attack
        Numpad 3    → Heavy Attack
        Numpad 4    → Combo String
        Numpad 5    → Special Move
        Numpad 0    → Crouch

    NOTE: In online multiplayer, only Player 1 bindings are needed
    (each player uses their own keyboard on their own computer).

────────────────────────────────────────────────────────────────────────────────
6.2 INPUT STATE TRACKING
────────────────────────────────────────────────────────────────────────────────

InputManager maintains a currentInput object, updated every keydown/keyup:

    currentInput = {
        forward     : false,
        backward    : false,
        left        : false,
        right       : false,
        jump        : false,        ← true on keydown, false on keyup
        jumpPressed : false,        ← single-frame true on keydown
        crouch      : false,
        lightAttack : false,        ← single-frame pulse on keydown
        medAttack   : false,
        heavyAttack : false,
        comboString : false,
        special     : false,
        specialHeld : float,        ← how long K has been held (seconds)
        block       : false,        ← computed: backward + opponent facing
        pause       : false,
    }

Single-frame pulses: set to true on keydown, reset to false after one frame.
This prevents "holding attack" from firing repeatedly.

────────────────────────────────────────────────────────────────────────────────
6.3 DOUBLE TAP DETECTION (for Dash)
────────────────────────────────────────────────────────────────────────────────

A double-tap is: same key pressed twice within 0.25 seconds.

    doubleTapTracker = {
        lastKey         : null,
        lastKeyTime     : 0,
        doubleTapWindow : 0.25,     ← seconds
    }

    On keydown event:
        currentTime = Date.now() / 1000
        if (key === lastKey && currentTime - lastKeyTime < doubleTapWindow) {
            → fire DASH event for that direction
            lastKey = null          ← reset to prevent triple-tap
        } else {
            lastKey = key
            lastKeyTime = currentTime
        }

    Dash fires as: input.dashForward = true  OR  input.dashBackward = true
    These are single-frame pulses consumed by CharacterController.

────────────────────────────────────────────────────────────────────────────────
6.4 BLOCK INPUT LOGIC
────────────────────────────────────────────────────────────────────────────────

Block is computed from raw input + character facing, not a direct key:

    function computeBlock(rawInput, character) {
        holdingBack = (character.facingDirection === 1 && rawInput.backward)
                   || (character.facingDirection === -1 && rawInput.forward)
        isNotAttacking = !character.isAttacking
        return holdingBack && isNotAttacking
    }

This ensures block always means "away from opponent" regardless of side.
If crouching + holding back → blockLow = true (blocks low attacks).

────────────────────────────────────────────────────────────────────────────────
6.5 SPECIAL MOVE INPUT (TAP vs HOLD)
────────────────────────────────────────────────────────────────────────────────

K key behaviour:
    On keydown K → start timer: specialHeldTime = 0
    Every frame while K held → specialHeldTime += deltaTime
    On keyup K:
        if specialHeldTime < 0.3s → fire FULL SPECIAL (costs 100% mana)
        if specialHeldTime >= 0.3s → fire HALF SPECIAL (costs 50% mana)

Characters without a half-special (Ryomen Raj's second combo is J+J,
not K-based) — K always fires full special regardless of hold time.

SECTION 7 — MOVEMENT & PHYSICS LOGIC
════════════════════════════════════════════════════════════════════════════════

────────────────────────────────────────────────────────────────────────────────
7.1 PHYSICS WORLD SETUP (Rapier.js)
────────────────────────────────────────────────────────────────────────────────

    const RAPIER = await import('@dimforge/rapier3d-compat')
    await RAPIER.init()
    physicsWorld = new RAPIER.World({ x:0, y:-20, z:0 })
    ← Gravity: -20 m/s² (stronger than real = snappier game feel)

PHYSICS OBJECTS:
    Ground      : Static flat plane collider at y=0
    Walls       : Static box colliders at arena boundary edges
    Character 1 : Dynamic capsule collider (height=1.6, radius=0.35)
    Character 2 : Dynamic capsule collider (same)
    Projectiles : Dynamic sphere colliders (Inferno Fist, 9 CGPA, Leetcode)

PHYSICS STEP: Called every frame before rendering.
    physicsWorld.step()
    → Read body position/rotation → Apply to Three.js model

────────────────────────────────────────────────────────────────────────────────
7.2 MOVEMENT LOGIC (Per Frame, in CharacterController.update)
────────────────────────────────────────────────────────────────────────────────

Each frame, movement is applied to the physics body's velocity:

    WALKING:
        moveDir = getInputDirection(input)  ← normalised x,z direction
        if (character.canAct && !character.isDashing) {
            velocity.x = moveDir.x * stats.walkSpeed
            velocity.z = moveDir.z * stats.walkSpeed
        }

    DASHING:
        On dash input:
            character.isDashing = true
            character.dashTimer = 0.3  ← seconds
            character.canAct = false   ← cannot attack first 0.3s
            dashVelocity = facingDirection * stats.dashSpeed
        While dashTimer > 0:
            dashTimer -= deltaTime
            velocity.x = dashVelocity
        When dashTimer <= 0:
            character.isDashing = false
            character.canAct = true

    JUMPING:
        On jump press (jumpCount < 2):
            velocity.y = calculateJumpVelocity(jumpHeight)
            ← formula: v = sqrt(2 * gravity * height)
            jumpCount++
            playAnimation("jump")
        When character lands (isGrounded = true):
            jumpCount = 0

    CROUCHING:
        On crouch hold:
            character.isCrouching = true
            → Scale capsule collider height by 0.6
            → Lower camera slightly
        On crouch release:
            character.isCrouching = false
            → Restore capsule height

    ARENA BOUNDARY CHECK:
        After velocity applied, check if new position exceeds arena limits:
            arenaRadius = 10.0  ← metres from centre
            if (distanceFromCentre > arenaRadius):
                clamp position to boundary
                zero out velocity pushing toward wall
                character.isOnWall = true

────────────────────────────────────────────────────────────────────────────────
7.3 GROUND DETECTION
────────────────────────────────────────────────────────────────────────────────

    isGrounded is true when:
        → Physics capsule is in contact with ground plane (y ≈ 0)
        → Rapier contact event: character body touching ground body

    isGrounded is false when:
        → In air after jump
        → Launched by attack (juggled)
        → Knocked down and in air

When isGrounded becomes true after jump:
    → playAnimation("landing")
    → camera shake: small 0.05 units for 0.1 seconds (heavy characters more)

────────────────────────────────────────────────────────────────────────────────
7.4 KNOCKBACK PHYSICS
────────────────────────────────────────────────────────────────────────────────

When a hit lands, knockback is applied to the struck character:

    LIGHT HIT knockback  : { x: 2.0 * opponent.facingDirection, y: 0.5 }
    MEDIUM HIT knockback : { x: 3.5 * opponent.facingDirection, y: 1.5 }
    HEAVY HIT knockback  : { x: 5.0 * opponent.facingDirection, y: 3.0 }
    LAUNCH (juggle)      : { x: 1.0 * opponent.facingDirection, y: 8.0 }
    WALL BOUNCE          : { x: -6.0 * opponent.facingDirection, y: 2.0 }

    ← facingDirection: which way attacker faces, so knockback goes away

    applyKnockback(struckCharacter, knockbackVector) {
        struckCharacter.physicsBody.applyImpulse(knockbackVector)
        struckCharacter.canAct = false
        struckCharacter.isAttacking = false
    }

════════════════════════════════════════════════════════════════════════════════

────────────────────────────────────────────────────────────────────────────────
8.1 THREE.JS ANIMATION MIXER
────────────────────────────────────────────────────────────────────────────────

Each character has a THREE.AnimationMixer attached to their model.
All animations are loaded as separate GLB files from Mixamo.

LOADING ANIMATIONS:
    const loader = new GLTFLoader()
    for each animationFile in animationList:
        gltf = await loader.loadAsync(animationFile)
        clip = gltf.animations[0]
        action = mixer.clipAction(clip)
        animations[animationName] = action

PLAYING AN ANIMATION:
    function playAnimation(character, name, options = {}) {
        if (character.currentAnimation === name) return
        ← Don't restart same animation

        previous = character.animations[character.currentAnimation]
        next = character.animations[name]

        if (options.crossFade) {
            previous.fadeOut(0.15)      ← 0.15s smooth blend out
            next.reset().fadeIn(0.15).play()
        } else {
            previous.stop()
            next.reset().play()
        }
        character.currentAnimation = name
    }

────────────────────────────────────────────────────────────────────────────────
8.2 ANIMATION PRIORITY RULES
────────────────────────────────────────────────────────────────────────────────

Animations have priority. Higher priority cannot be interrupted by lower:

    PRIORITY 5 (Highest) : rageArt, knockedDown
    PRIORITY 4           : special, hitStun, guardBreak
    PRIORITY 3           : attack animations (all)
    PRIORITY 2           : jump, doubleJump, dash
    PRIORITY 1           : crouch, crouchWalk
    PRIORITY 0 (Lowest)  : idle, walk, run

Before playing any animation:
    if (newPriority < currentAnimationPriority) → ignore request
    if (newPriority >= currentAnimationPriority) → play new animation

────────────────────────────────────────────────────────────────────────────────
8.3 ANIMATION → MOVEMENT SYNC
────────────────────────────────────────────────────────────────────────────────

    isWalking + forward    → play "walk" (crossFade from idle)
    isWalking + any dir    → play "walk" (all directions use same anim)
    speed > 8.0 (dash)     → play "run"
    isJumping              → play "jump"
    doubleJump             → play "double_jump" (can be same as jump)
    isCrouching + still    → play "crouch_idle"
    isCrouching + moving   → play "crouch_walk"
    isBlocking             → play "block"
    not moving, grounded   → play "idle"

Attack animations override movement animations for their duration.
After attack recovery ends → return to idle/walk based on movement input.

────────────────────────────────────────────────────────────────────────────────
8.4 ANIMATION MIXER UPDATE (Game Loop)
────────────────────────────────────────────────────────────────────────────────

Every frame in the game loop:
    player1.mixer.update(deltaTime)
    player2.mixer.update(deltaTime)

deltaTime = time since last frame in seconds (typically ~0.016 for 60 FPS)
This advances all animation clips forward by the correct amount.

────────────────────────────────────────────────────────────────────────────────
9.1 ATTACK INITIATION
────────────────────────────────────────────════════════════════════════════════

When player presses an attack button:

    function initiateAttack(character, moveType) {
        // Gate: can only attack if free to act
        if (!character.canAct) return
        if (!character.isGrounded && moveType === 'comboString') return
        if (character.currentMana < moveCost) return  ← for specials

        character.isAttacking = true
        character.canAct = false
        character.attackPhase = "startup"
        character.attackFrameTimer = move.startupFrames
        character.currentMove = move

        playAnimation(character, move.animation)
        // Hitbox not active yet — character is in startup frames
    }

────────────────────────────────────────────────────────────────────────────────
9.2 ATTACK FRAME DATA & HITBOX LIFECYCLE
────────────────────────────────────────────────────────────────────────────────

Attack moves through 3 phases, tracked by frame counter:

    STARTUP PHASE  (e.g. 6 frames)
        → Character winding up
        → Hitbox: INACTIVE
        → Character: cannot be cancelled, cannot act
        → Vulnerable to being hit (interrupts attack)

    ACTIVE PHASE   (e.g. 4 frames)
        → Hitbox: ACTIVE — can register hits
        → Hit is only registered ONCE per attack (hitRegistered flag)
        → If hit registered: fire damage, play hit effects
        → If no hit by end of active phase: attack "whiffs" (miss)

    RECOVERY PHASE (e.g. 8 frames)
        → Hitbox: INACTIVE
        → Character returning to neutral
        → Cannot act (vulnerable to punishment)
        → When recovery ends: canAct = true, isAttacking = false

    Frame counting (60 FPS game = 60 frames per second):
        attackFrameTimer -= 1 each frame
        0 frames remain → advance to next phase

────────────────────────────────────────────────────────────────────────────────
9.3 HITBOX SYSTEM
────────────────────────────────────────────────────────────────────────────────

Hitboxes are defined per move as offsets from character position.
They are checked geometrically each frame during active phase.

HITBOX STRUCTURE:
    hitbox = {
        offset : {x, y, z}  ← world position = character.position + offset
        size   : {x, y, z}  ← half-extents of box
    }
    ← Adjusted based on character.facingDirection for correct side

HURTBOX (the region that receives hits):
    Each character has a standing hurtbox and a crouching hurtbox.
    Standing hurtbox  = capsule from head to feet (full height)
    Crouching hurtbox = capsule shortened by 40% (low profile)

HIT DETECTION (checked every frame during active phase):
    function checkHit(attacker, defender) {
        hitboxWorld = attacker.position + (attacker.currentMove.hitboxOffset
                      * attacker.facingDirection)
        hurtboxWorld = defender.position

        // AABB intersection check:
        overlapX = abs(hitboxWorld.x - hurtboxWorld.x) < (hitboxSize.x + hurtboxRadius)
        overlapY = abs(hitboxWorld.y - hurtboxWorld.y) < (hitboxSize.y + hurtboxHeight/2)
        overlapZ = abs(hitboxWorld.z - hurtboxWorld.z) < (hitboxSize.z + hurtboxRadius)

        if (overlapX && overlapY && overlapZ && !attacker.hitRegistered) {
            attacker.hitRegistered = true
            registerHit(attacker, defender, attacker.currentMove)
        }
    }

NOTE: Z-axis check has generous tolerance (±1.5m) since game is pseudo-3D
      and players may not be perfectly aligned on Z axis.

────────────────────────────────────────────────────────────────────────────────
9.4 HIT REGISTRATION (registerHit function)
────────────────────────────────────────────────────────────────────────────────

When a hit is confirmed:

    function registerHit(attacker, defender, move) {

        // 1. CHECK INVULNERABILITY
        if (defender.isInvulnerable) return

        // 2. CHECK BLOCKING
        if (isBlocking(defender, move)) {
            applyBlockedHit(attacker, defender, move)
            return
        }

        // 3. APPLY DAMAGE
        rawDamage = move.damage
        scaledDamage = applyComboScaling(rawDamage, defender.comboCounter)
        defender.currentHP = max(0, defender.currentHP - scaledDamage)

        // 4. MANA GAIN
        attacker.currentMana = min(100, attacker.currentMana + move.manaGain)
        defender.currentMana = min(100, defender.currentMana + 5)

        // 5. APPLY KNOCKBACK
        applyKnockback(defender, move.knockback, attacker.facingDirection)

        // 6. HIT STUN
        defender.hitStunTimer = move.hitStunFrames
        defender.canAct = false
        defender.isAttacking = false

        // 7. SPECIAL HIT EFFECTS
        if (move.causesLaunch)      → launcher logic
        if (move.causesWallSplat)   → wall splat logic
        if (move.causesGroundBounce)→ ground bounce logic

        // 8. INCREMENT COMBO COUNTER
        attacker.comboCounter++

        // 9. PLAY EFFECTS
        playHitEffect(defender.position, move.hitEffect)
        SoundSystem.play(attacker.data.sounds.punchLight)  ← or relevant sound
        playAnimation(defender, isHighHit ? "hit_high" : "hit_low")
        updateHealthBar(defender)

        // 10. CHECK ROUND END
        if (defender.currentHP <= 0) triggerRoundEnd(attacker, defender)
    }

────────────────────────────────────────────────────────────────────────────────
9.5 BLOCKING LOGIC
────────────────────────────────────────────────────────────────────────────────

    function isBlocking(defender, move) {
        if (!defender.isBlocking) return false
        if (move.isUnblockable) return false

        // High/Mid attacks: blocked by standing block
        if (move.hitHeight === "high" || move.hitHeight === "mid") {
            return defender.isBlocking && !defender.isCrouching
        }

        // Low attacks: only blocked by crouch + block
        if (move.hitHeight === "low") {
            return defender.isBlocking && defender.isCrouching
        }
        return false
    }

    function applyBlockedHit(attacker, defender, move) {
        // Chip damage (10% of move damage)
        chipDamage = move.damage * 0.10
        defender.currentHP = max(0, defender.currentHP - chipDamage)

        // Guard meter drain
        guardDrain = move.guardDamage || (move.damage * 0.5)
        defender.guardMeter = max(0, defender.guardMeter - guardDrain)

        // Guard break check
        if (defender.guardMeter <= 0) {
            triggerGuardBreak(defender)
        }

        // Attacker still gains mana on blocked hit
        attacker.currentMana = min(100, attacker.currentMana + 5)

        // Visual: block spark effect
        // Sound: block sound
        playBlockEffect(defender.position)
        SoundSystem.play("ui/block.mp3")
        updateHealthBar(defender)    ← chip damage shows
    }

────────────────────────────────────────────────────────────────────────────────
9.6 GUARD BREAK
────────────────────────────────────────────────────────────────────────────────

    function triggerGuardBreak(defender) {
        defender.isBlocking = false
        defender.canAct = false
        defender.isInGuardBreakStun = true
        defender.guardBreakTimer = 1.5  ← 1.5 seconds stagger
        defender.guardMeter = 0         ← stays at 0

        playAnimation(defender, "guard_break_stun")
        ← guard break plays a specific stagger animation

        // Restore guard meter slowly during stun (starts recovering after)
        // Guard meter refills at 20% per second when not being hit
    }

────────────────────────────────────────────────────────────────────────────────
9.7 COMBO SCALING
────────────────────────────────────────────────────────────────────────────────

Each hit in a combo deals less damage to prevent infinite loops:

    comboScaleTable = [
        1.00,   ← hit 1 (full damage)
        1.00,   ← hit 2
        0.90,   ← hit 3
        0.80,   ← hit 4
        0.70,   ← hit 5
        0.60,   ← hit 6
        0.50,   ← hit 7
        0.40,   ← hit 8+
    ]

    function applyComboScaling(rawDamage, comboCounter) {
        idx = min(comboCounter, comboScaleTable.length - 1)
        return rawDamage * comboScaleTable[idx]
    }

comboCounter resets when:
    → Defender lands on ground (fully grounded)
    → Defender successfully blocks
    → Round ends

────────────────────────────────────────────────────────────────────────────────
9.8 WALL INTERACTIONS
────────────────────────────────────────────────────────────────────────────────

    WALL SPLAT:
        Triggered when: defender is knocked into boundary wall
        Detection: defender.position reaches arenaRadius limit while
                   knockback velocity is still active

        Effect:
            defender.isWallSplatted = true
            defender.wallSplatTimer = 0.8  ← 0.8 second stun at wall
            defender.velocity = { x:0, y:0, z:0 }  ← pinned to wall
            play wall crack particle effect at impact point
            camera shake: 0.1 units, 0.15 seconds

    WALL BOUNCE:
        Triggered when: heavy attack connects on wall-splatted defender

        Effect:
            defender.isWallSplatted = false
            apply bounceKnockback: { x: -8 * attacker.facingDirection, y: 2 }
            ← flies back toward centre
            attacker has ~0.7 seconds to dash in and continue combo

────────────────────────────────────────────────────────────────────────────────
9.9 AIR JUGGLING
────────────────────────────────────────────────────────────────────────────────

Juggling occurs when defender is hit while airborne (after launch):

    LAUNCH:
        move.causesLaunch = true
        Apply strong upward knockback: { x: 1.5, y: 9.0 }
        defender.isJuggling = true
        defender.juggleCounter = 0
        defender.isInvulnerable = false  ← can be hit in air

    JUGGLE HITS:
        While defender.isJuggling = true:
            Light and Medium attacks can hit
            Each air hit: juggleCounter++
            Gravity gradually increases per juggle hit
            Air combo scaling: starts at 0.7 multiplier from first air hit

    JUGGLE END:
        When defender lands on ground:
            defender.isJuggling = false
            defender.juggleCounter = 0
            play "knockedDown" animation
            defender.isKnockedDown = true
            defender.getUpTimer = 1.0  ← 1 second before can get up

    TECH ROLL (Optional - future feature):
        On landing from juggle: press Light Attack to tech roll
        Rolls character to side, skips knockdown state

────────────────────────────────────────────────────────────────────────────────
15.1 GAMEPLAY CAMERA
────────────────────────────────────────────────────────────────────────────────

The camera always keeps both fighters visible.

    MIDPOINT TRACKING:
        midpoint = (player1.position + player2.position) / 2

    DISTANCE CALCULATION:
        fightDistance = Vector3.distance(player1.position, player2.position)
        cameraDistance = baseDistance + (fightDistance * zoomFactor)
        baseDistance = 8.0 metres
        zoomFactor = 0.6  ← zooms out 0.6 for every extra metre apart

    CAMERA POSITION:
        camera.position.x = midpoint.x
        camera.position.y = midpoint.y + 3.0  ← elevated above fight
        camera.position.z = midpoint.z + cameraDistance

    CAMERA TARGET (lookAt):
        camera.lookAt(midpoint)

    SMOOTHING (prevents jitter):
        actualPos = lerp(actualPos, targetPos, 0.08 * deltaTime * 60)
        ← Smooth interpolation at ~8% per frame toward target

    VERTICAL TRACKING:
        If fighters jump high: camera follows midpoint Y up to 2 metres max
        Returns to base Y smoothly when fighters land

    MINIMUM DISTANCE (prevent extreme close-up):
        cameraDistance = max(6.0, cameraDistance)

    MAXIMUM DISTANCE (arena boundary):
        cameraDistance = min(15.0, cameraDistance)

16.3 SOUND PLAYBACK
────────────────────────────────────────────────────────────────────────────────

    function playSound(key, options = {}) {
        buffer = soundBuffers[key]
        if (!buffer) return

        source = audioContext.createBufferSource()
        source.buffer = buffer

        gainNode = audioContext.createGain()
        gainNode.gain.value = options.volume || 1.0

        source.connect(gainNode)
        gainNode.connect(audioContext.destination)

        source.start(options.startOffset || 0)
        return source  ← returned so it can be stopped if needed
    }

16.5 MUSIC SYSTEM

    currentMusic = null
    currentMusicSource = null

    function playMusic(key, fadeTime = 1.0) {
        if (currentMusicSource) {
            // Fade out current
            currentMusicGain.gain.linearRampToValueAtTime(0, audioCtx.currentTime + fadeTime)
            setTimeout(() => currentMusicSource.stop(), fadeTime * 1000)
        }

        source = createBufferSource(soundBuffers[key])
        source.loop = true

        newGain = audioContext.createGain()
        newGain.gain.value = 0
        newGain.gain.linearRampToValueAtTime(0.6, audioCtx.currentTime + fadeTime)
        ← Fade in new track

        source.connect(newGain)
        newGain.connect(musicGain)
        source.start()

        currentMusicSource = source
        currentMusicGain = newGain
    }

18.3 AI DECISION CYCLE
────────────────────────────────────────────────────────────────────────────────

AI makes decisions every decisionInterval (0.3s to 0.8s based on difficulty).
Between decisions: continues current action.

    function AIDecide(ai, player) {
        distance = getDistance(ai, player)
        playerHP = player.currentHP
        aiHP = ai.currentHP
        aiMana = ai.currentMana
        playerJustWhiffed = player.isInRecovery

        // Priority 1: Punish player whiff
        if (playerJustWhiffed && distance < attackRange) {
            → AI_STATE_PUNISH
            executeHeavyAttack()
            return
        }

        // Priority 2: Retreat if low HP
        if (aiHP < retreatHPThreshold && distance < safeDistance) {
            → AI_STATE_RETREAT
            dashBackward()
            return
        }

        // Priority 3: Use special if mana full
        if (aiMana >= 100 && Math.random() < specialUseChance) {
            → AI_STATE_SPECIAL
            useSpecialMove()
            return
        }

        // Priority 4: Block if player attacking
        if (player.isAttacking && Math.random() < blockChance) {
            → AI_STATE_DEFEND
            holdBlock()
            return
        }

        // Priority 5: Approach and attack if far
        if (distance > attackRange) {
            → AI_STATE_APPROACH
            moveTowardPlayer()
            return
        }

        // Priority 6: Pressure with attacks
        if (distance <= attackRange && Math.random() < attackChance) {
            → AI_STATE_PRESSURE
            selectAndExecuteAttack()
            return
        }

        // Default: idle movement
        → AI_STATE_IDLE
        smallRandomMovement()
    }

    function AIReactToPlayerAttack(ai, player) {

    }

19.3 INPUT SYNCHRONISATION
────────────────────────────────────────────────────────────────────────────────

Each frame, the local player's input is sent to the remote player.
The remote player's input is received and applied to the remote character.

    LOCAL PLAYER:
        Every frame → room.send({ type: "input", data: localInputState })

    REMOTE PLAYER:
        room.onmessage = (event) => {
            msg = JSON.parse(event.data)
            if (msg.type === "input") {
                remoteInput = msg.data
                applyInputToCharacter(player2, remoteInput)
            }
        }

    Both players run the same physics simulation locally.
    Inputs keep both simulations in sync.
    Small latency is acceptable for a friends-casual game.

SECTION 20 — GAME LOOP (main.js)
════════════════════════════════════════════════════════════════════════════════

The game loop runs at 60 FPS using requestAnimationFrame.

    let lastTime = 0

    function gameLoop(timestamp) {
        rawDeltaTime = (timestamp - lastTime) / 1000  ← in seconds
        lastTime = timestamp

        // Cap delta to prevent spiral of death on slow frames
        rawDeltaTime = Math.min(rawDeltaTime, 0.033)  ← max 33ms

        // Apply time scale (slow motion, etc.)
        deltaTime = rawDeltaTime * timeScale

        // Only update game systems during active combat
        if (gameState === STATE_FIGHTING) {

            // 1. Update input
            InputManager.update()

            // 2. Update physics world
            physicsWorld.step()

            // 3. Update characters
            player1Controller.update(deltaTime, player1Input)
            player2Controller.update(deltaTime, player2Input)

            // 4. Check combat (hitboxes, hits)
            CombatSystem.update(player1Controller, player2Controller)

            // 5. Update animations
            player1Controller.mixer.update(deltaTime)
            player2Controller.mixer.update(deltaTime)

            // 6. Update camera
            CameraController.update(deltaTime)

            // 7. Update timers (round timer, hitStun timers, etc.)
            updateAllTimers(deltaTime)

            // 8. Update visual effects (particles, shaders)
            updateVisualEffects(deltaTime)

            // 9. Update HUD
            UIManager.updateHUD()

            // 10. Send network inputs (multiplayer)
            if (isMultiplayer) NetworkManager.sendInput()
        }

        // Always render
        renderer.render(scene, camera)

        requestAnimationFrame(gameLoop)
    }

    requestAnimationFrame(gameLoop)  ← start the loop

SECTION 21 — PERFORMANCE TARGETS & OPTIMISATION
════════════════════════════════════════════════════════════════════════════════

TARGET HARDWARE     : Mid-range laptop (Intel i5, 8GB RAM, integrated graphics)
TARGET FPS          : Stable 60 FPS at 1280x720 resolution
FALLBACK FPS        : 30 FPS at 1024x600 on very low-end hardware

OPTIMISATION RULES:
    ─────────────────────────────────────────────────────────
    1. MODELS:
       Max polygon count per character : 15,000 triangles
       Max polygon count per arena     : 30,000 triangles
       Texture resolution per char     : 1024x1024 maximum
       Texture format                  : WebP (better compression than PNG)
       LOD (Level of Detail)           : Not needed at this scale

    2. DRAW CALLS:
       Merge static arena meshes into one draw call where possible
       Character: max 3 draw calls (body, hair, accessory)
       Arena: max 5 draw calls total

    3. SHADOWS:
       No real-time dynamic shadows (too expensive for integrated GPU)
       Use baked shadow maps on arena floor (pre-rendered texture)
       Character shadow: simple blob shadow (flat circle under character)

    4. PHYSICS:
       Run physics at 60Hz (matches render loop)
       Only 2 character capsules + ground + 4 wall planes = minimal
       Projectiles: simple AABB check, no physics body needed

    5. PARTICLES:
       Particle pool: 20 systems max active simultaneously
       Max 40 particles per system
       Particles are THREE.Points (one draw call per system)

    6. RENDERER SETTINGS:
       renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))
       → Caps at 2x for retina, prevents 3x on high-DPI phones
       renderer.shadowMap.enabled = false
       renderer.antialias = true (acceptable cost for quality)
